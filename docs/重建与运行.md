## 已部署设备

在 Orin 本机浏览器打开 `http://127.0.0.1:8765`。从 Mac 可以经现有 SSH 查看服务状态。校准时使用 Orin 本机页面，或者运行命令行版，后者只返回位置数字。若在 Mac 浏览器访问，可在 Mac 终端运行 `ssh -N -L 8765:127.0.0.1:8765 orin`，再打开 `http://127.0.0.1:8765`。点「开始语音提问」调用的是 Orin 麦克风。

```bash
ssh orin 'cd Documents/orin-desk-agent && bash stack.sh status'
ssh orin 'cd Documents/orin-desk-agent && bash stack.sh start'
ssh orin 'cd Documents/orin-desk-agent && bash stack.sh stop'
ssh -t orin 'cd Documents/orin-desk-agent && .venv/bin/python calibrate.py'
```

`stack.sh` 管理 tmux 中的 vision、qwen 和 cosmos 窗口，编译和测试窗口独立。看板、Qwen 和 Cosmos 分别绑定 `127.0.0.1:8765`、`:8081`、`:8082`。数据库文件为项目目录下的 `data.sqlite3`，现场校准为 `calibration.json`，请留在 Orin。应用默认不留存音视频，也不默认保存语音对话文本。在看板点「开始语音提问」，说完点「结束录音」。识别和答复都显示在「本地问答」，久坐和定时提醒显示在「目标与提醒」。

## 从源码重建

1. 在 Mac 解压源码归档。用 `scp` 将归档传到 Orin，解包在 `~/Documents/orin-desk-agent`。现有部署先备份数据库和校准文件，重建引擎前停止项目服务。另一个 Orin 需准备指向该设备的 `ssh orin` 别名。
2. 在 Orin 核验 L4T 和磁盘空间。在已配置 Jetson APT 源的设备上，按需执行 `sudo bash install-system.sh`。脚本安装依赖，并配置 Docker 的 NVIDIA runtime 与当前用户的 docker 组权限。Orin L4T 与 TensorRT 版本变化时需重新生成视觉引擎。
3. 在 Mac 的解压目录执行以下模型下载命令。下载阶段需要网络。脚本将公开模型传到 Orin。最后在 Orin 复核所有输入权重。

   ```bash
   for group in small voice qwen cosmos; do bash fetch-models.sh "$group"; done
   ssh orin 'cd Documents/orin-desk-agent && sha256sum -c MODEL-SHA256SUMS'
   ```

4. 在 Orin 项目目录运行 `bash prepare-build.sh`，创建应用 Python 环境并下载固定提交的 whisper.cpp 和 llama.cpp。运行 `bash rebuild-vision.sh` 生成 FP16 视觉引擎，运行 `bash build-runtime.sh` 编译两个 CUDA 运行时。运行时构建建议放在 tmux 中。
5. 运行 `bash setup-cuda-libs.sh`、`bash setup-cudss.sh`、`bash setup-cosmos.sh`、`bash check-cosmos-gpu.sh`。下载失败时可以在 Mac 解压目录运行 `bash relay-cosmos-deps.sh` 转传两个 CUDA Python wheel，再回到 Orin 重跑安装。当前 Cosmos 实机路径为 Transformers CUDA。
6. 在 Orin 执行 `bash stack.sh start`。用 `bash stack.sh status` 查看是否全部就绪。分别核对 `logs/07-vision.log`、`logs/07-qwen.log` 和 `logs/07-cosmos.log`。

## 校准与验收

坐站无需贴桌贴或记录肩高。RTMPose 使用关节之间的相对角度。遮挡时可用相对人体尺寸的短时起落轨迹，背景移动会清空该轨迹，证据不足再由本机 Cosmos 复核工位画面。在本机看板的「现场校准」圈选工位可以减少背景干扰，摄像头移动后如果工位已经移出区域，重新圈选即可。桌面档位单独圈选自然桌沿的运动区域，分别记录低档与高档。桌沿校准可选，用户已跳过三轮实桌验证。现场验收关注 30 分钟姿态标注和 10 条麦克风指令。离线运行使用网络隔离审查。

自动化预检用 `cosmos-smoke.py`、`qwen-smoke.py`、`voice-smoke.py`。其中 Cosmos 使用 `.cosmos/bin/python`，其余使用 `.venv/bin/python`。语音 CUDA 验证进程需将 `/usr/local/cuda/lib64` 加入 `LD_LIBRARY_PATH`。预检使用合成素材，语音测试读取随源码提供的测试 WAV，使用临时 SQLite 数据。两小时技术压测可在 Orin 的 tmux 中运行 `bash soak-load.sh`，日志保存在本机项目目录。

在 Orin 项目目录运行 `bash offline-model-smoke.sh --with-qwen` 可验证离线运行。脚本使用仅含回环网卡的独立网络命名空间，加载本地 Cosmos、Whisper、Qwen，检查看板 HTTP 接口、SQLite 统计和文字提醒。测试用合成画面、测试 WAV 与临时 SQLite 数据，设备原有网络和实时摄像头服务继续工作。Orin 本机的 `http://127.0.0.1:8765` 在无外网时仍可访问。

### 现场验收脚本

在 Orin 项目目录按下列顺序运行，建议在桌前的 Orin 本机终端完成。测试操作由现场人员触发。

```bash
.venv/bin/python field-check.py pose --with-cosmos
.venv/bin/python voice-field-check.py
.venv/bin/python cosmos-field-check.py
```

姿态脚本引导共约 30 分钟的坐姿、站姿、转椅、遮挡和离开。在看板显示视觉检测恢复后开始。坐站计时从操作员确认就位开始，离开段留 5 秒走出画面。每段结束时，仅在实际按提示操作的情况下输入 `y`。正式误差、切换和 Cosmos 对照只使用已确认区间。按键时已经匹配的切换单列，P95 只汇总按键后实际观察到的就位切换。按用户调整，语音脚本默认使用实体麦克风做 10 条普通话指令，请按提示在安静和轻微背景噪声下实测。它只保留通过状态、工具核对结果与时延。核对任务类型、正文和提醒时间后，脚本删除测试待办和长延时提醒。语音时延为提交结束录音到得到文字答复。姿态脚本的 `--with-cosmos` 选项在同一轮动作中抽查 12 个坐、站、离开的单帧，记录标签一致性、未知、错误、输入尺寸与 P95。也可以单独运行 Cosmos 脚本。照片在 Orin 内存处理，日志只保留标签及测量值。

## 工位在位与持续运行

在「现场校准」将「桌前人物区域」圈在工位。检测到人时开始计时。坐站关键点不清晰时，可以记录在位但姿态未知。看板和麦克风都可查询「我今天在工位待了多久」。画面太暗时暂停视觉推理，恢复稳定亮度后自动继续。

在 Orin 项目目录运行 `bash install-autostart.sh`，保留现有 crontab 并添加本项目的启动与监督项。它在启动后和每分钟检查 tmux 服务窗口。用 `bash stack.sh stop` 暂停项目和自动拉起，用 `bash stack.sh start` 恢复。麦克风依赖 Orin 的本地音频会话。

24 小时采样可用以下命令启动。在 Orin 的 tmux 运行，使用新的输出文件名。

```bash
stamp=$(date +%Y%m%d-%H%M%S)
.venv/bin/python measure.py --require-models --seconds 86400 --interval 30 \
  --output "logs/24h-agent-${stamp}-metrics.jsonl" \
  > "logs/24h-agent-${stamp}-summary.json"
```

摄像头过暗或无帧时立即暂停预览和视觉检测。默认北京时间 08:00–18:00，持续约 3 秒后看板显示「隐私保护中」，时间轴和今日统计单列隐私保护时长。其余时段的黑屏沿用暗场暂停。有效亮度稳定约 2 秒后恢复工位检测。

## 可选的 Cosmos vLLM 后端

当前常驻服务使用完成两小时联跑的 Transformers CUDA。已单独验证 vLLM CUDA 可在相同 Orin 离线运行 Cosmos3-Edge。以下为 L4T R36.4.4、CUDA 12.6 和 SM 8.7 的重建路径，建议在 tmux 内执行编译。

1. 在 Orin 解压固定的 vLLM 提交。已有源目录时先确认其版本。

   ```bash
   cd ~/Documents/orin-desk-agent
   mkdir -p runtime/vllm-cosmos-src
   wget -O runtime/vllm-cosmos-src.tar.gz \
     https://codeload.github.com/vllm-project/vllm/tar.gz/894ebb27f5c7d7f8758266163ffd503132e432d2
   tar -xzf runtime/vllm-cosmos-src.tar.gz --strip-components=1 -C runtime/vllm-cosmos-src
   ```

2. 在 Mac 解压目录运行 `bash relay-vllm-sources.sh`，将固定版本的 CUTLASS、Triton 和 FlashAttention 等源码传到 Orin。先按前文构建 Cosmos 的 CUDA 依赖，再在 Orin 依次运行：

   ```bash
   bash prepare-vllm-runtime.sh
   bash probe-vllm-build.sh
   bash build-vllm-cuda.sh
   bash register-vllm-orin.sh
   bash probe-vllm-serve.sh
   ```

3. 安装脚本使用 Orin ARM64 的 Triton 3.5.1，编译 Ampere 所需的原生组件和 FlashAttention 2。注册脚本处理 Transformers 5.17 的图像工具导入，以及 Reasoner 应跳过的生成分支权重。探测脚本在只有回环网卡的隔离环境启动 vLLM，用合成单帧和三帧测试应用的摘要逻辑。当前生产运行保留经过两小时测量的 Transformers。

若已验证本机源码和探测通过，可在维护窗口切换。先用 `touch .cosmos-vllm` 选用 vLLM，再用 `bash stack.sh stop`，等待项目窗口退出，再用 `bash stack.sh start` 启动。删除该文件并再次重启即可切回 Transformers。两条路径均使用本地模型和回环端口。

语音现场测试默认使用文字模式。已有同一模式的日志时，可用 `--resume logs/field-voice-时间戳.jsonl --start-at 条目编号` 续测。

Orin 每次开始录音时重新选择输入，优先使用当前可用的 Insta360 输入。需要固定设备时，在启动服务的环境中设置 `ORIN_AUDIO_SOURCE`。
