# Goal · 在 Jetson AGX Orin 上交付全离线桌前个人助手

**执行指令**
以本文为实施和验收依据，在用户的 Jetson AGX Orin 64GB 上搭建可重复启动的原型。按阶段执行，每阶段记录版本、配置、实测结果和待办。遇到需要用户现场操作的步骤，集中说明操作与预期结果，同时继续能独立完成的工作。最终用真实外设与固定机位完成端到端验收。

## 已知条件

- 设备为 Jetson AGX Orin 64GB，已有 Ubuntu 22.04.5 LTS 和经 Tailscale 验证过的 SSH。实际 L4T、CUDA、TensorRT、磁盘余量和音视频外设状态以本次上机为准。
- 摄像头只能固定在电脑桌斜后方。桌面可以升降。固定参照应独立于升降桌，镜头尽量同时覆盖自然桌沿、人物坐站和离开路径。坐站判断需适应机位适度移动，禁止使用固定肩高或其他绝对画面高度。
- 摄像、收音、推理和个人数据存储全在 Orin。依赖和模型可在部署期下载，运行时使用本机服务。应用默认只监听本机，已有 Tailscale 用于开发维护。视频和音频默认仅在内存短暂处理，数据库记录活动事件与用户选择保留的文本。

## 交付范围

1. 记录桌面高低档和人在桌前的坐、站、离开、未知状态。支持可调的久坐提醒、今日坐站时长和站立目标。
2. 用 NVIDIA Cosmos3-Edge Reasoner 复核选定画面并生成可见行为摘要，例如起身或离开。看板显示桌前活动、粗略朝向和未知区间。
3. 看板提供中文按键语音问答，使用 Orin 麦克风，页面显示识别结果与文字答复。可查询坐站数据、设定文字提醒和添加本地待办。
4. 提供本机看板，展示桌面档位、活动时间轴、站立目标、提醒、已保存对话与 Cosmos 摘要。
5. 24 小时监测工位在位时长。以工位区域内是否检测到人为依据，在姿态未知时仍可计入在位。默认按单人专用工位统计。画面过暗时暂停推理，恢复稳定亮度后继续。白天持续黑屏或无帧时单列为隐私保护时间。

## 实施顺序

### 0. 上机核验与现场校准

- 通过现有 SSH 核验主机、架构、L4T、可用内存和磁盘，以及 CUDA、TensorRT 和容器运行时。可用 `dpkg-query -W nvidia-l4t-core`、`free -h`、`df -h`、`lsblk`、`nvpmodel -q`。记录功耗档位，构建镜像和缓存前确认磁盘空间。
- 用 `v4l2-ctl --list-devices` 和 `arecord -l` 核验摄像头及麦克风，分别实测取帧和录音。
- 检查摄像头能否看见自然桌沿及人体关节。可选桌面档位可单独圈定桌沿运动范围。坐站直接用真人动作试测，包括前倾、后仰、转椅、站直和离开。记录机位及遮挡情况。

### 1. 实现桌面与人的两条状态时间线

- 用轻量图像检测跟踪自然桌沿，输出低档、高档、过渡、未知。常用档位参考只用于桌面。摄像头明显移动时需重选桌沿或重新校准桌面。
- 用 YOLO26m-Pose 同时输出人体框与 17 个关节，再用肩、髋、膝和踝之间的相对角度判断坐站。关节遮挡时尝试相对于人体大小的起落轨迹，先检查静态背景是否移动，再用本机 Cosmos 复核工位局部画面。部署从 ONNX → TensorRT FP16 起步。
- 桌面档位与人体姿态独立记录。高档且无人记为离开。低档起身、高档仍坐等情况按可见姿态处理。证据不足记为未知，短时遮挡保留久坐会话，未知时段单列。确认站起或离开后结束本次久坐会话。
- 用 SQLite 保存桌面事件、人体状态区间、提醒和目标。用本地日期切分跨午夜的区间，掉线和重启间隙记为未知。提供配置、查询接口及最简看板。

### 2. 实现本地语音和工具调用

- 按键说话配合 VAD。用 whisper.cpp 多语种 base 起步，在同一组中文录音上对比 small 的延迟和正确率。语音作为输入，转写和回复在看板显示。久坐和定时提醒写入看板。
- 用 llama.cpp CUDA 部署 Qwen3.5-4B 文本 Q4_K_M。初始上下文 4K，语音短答关闭思考模式。统计查询从数据库取数并可用模板直答。开放式问答和任务路由走 Qwen。
- 工具仅开放本地统计查询、设提醒和添加待办等已定义操作。程序校验参数和任务结果，重试时避免重复写入。将对话与任务结果接入看板。

### 3. 接入 Cosmos 和整机调度

- 按实际 L4T 选择并固定兼容的 Orin vLLM 运行环境，先跑通 Cosmos3-Edge 的 Reasoner 单帧样例。Jetson AI Lab 在同款 Orin 上公布约 45 tok/s 图像或视频解码数据，验收另测整次请求耗时。Qwen 的 Q4 权重约 2.7 GB，两个模型联跑时实际内存需计入缓存、容器和系统开销。
- 从内存环形缓冲选取变化前后的关键帧，优先裁到人物和椅子。先接单帧，再验证 2–4 张关键帧。模型输出限制为可见事实或「无法判断」，摘要写入看板。
- 语音与姿态采样优先。Cosmos 异步单请求执行，待处理队列最多保留一个事件。限制视觉输入、上下文与输出长度。记录空闲、单模型及联跑三种情况下的延迟、内存、温度和频率。

### 4. 工位计时与 24 小时运行

- 工位在位由人员检测和画面复核共同判断，坐站继续用相对关节、短时轨迹与本机视觉复核。
- 画面过暗或无帧时暂停预览、人物、姿态、桌沿和 Cosmos 视觉处理。北京时间 08:00–18:00，黑屏或无帧持续约 3 秒后单列为隐私保护时间。有效亮度持续约 2 秒后恢复。其余暗场、掉线和程序重启间隙记为未知。
- 在 Orin 上使用用户 cron 启动与监督 tmux 服务。设备启动后继续本机采样。

## 完成条件

| 验收项 | 测法与首版目标 |
| --- | --- |
| 升降桌档位 | 可选功能。用户明确跳过三轮现场升降；桌高不参与人的坐站判断。 |
| 活动统计 | 人工标注约 30 分钟实际机位样本，覆盖前倾、转椅、站着用电脑、遮挡、离开。视觉状态更新 ≥5 FPS，有效切换延迟 P95 ≤3 秒，坐时与站时累计误差各 ≤5%。同时报告未知时长、占比及误提醒。 |
| 中文语音 | 10 条代表性指令，覆盖查询、提醒、待办和背景噪声。任务完成率 ≥90%，常见任务结束录音至文字答复 P95 ≤3 秒，开放问答 P95 ≤5 秒。 |
| Cosmos 摘要 | 对同机位人工标注事件验证摘要与画面一致，记录错误和未知。单帧提交至摘要完成 P95 ≤8 秒，报告测试请求数和输入尺寸。 |
| 整机联跑 | 摄像、看板、语音与周期性 Cosmos 请求联跑至少 2 小时。姿态与语音达到前述目标，记录峰值 RAM、swap 和温度。无 OOM 或持续 swap 增长，目标保留约 8 GiB 内存余量。 |
| 工位在位 | 结合姿态标注验证在位、遮挡、离开和重新出现。记录镜头覆盖与照明。 |
| 24 小时运行 | 验证 tmux 服务退出自动恢复。运行满 24 小时后记录掉线、存储增长和暗场暂停，另在有现场维护窗口时检查 Orin 重启后的自动启动。 |
| 离线运行 | 按用户决定，以源码审查和仅回环网络命名空间实测验证。测试覆盖本机看板、测试 WAV 转写、Qwen 问答、Cosmos 摘要及 SQLite 提醒。 |

以上数值为原型验收目标。每项记录实测值与通过状态。遇到差距，先定位瓶颈，调整采样、队列、上下文或部署方式后复测。
