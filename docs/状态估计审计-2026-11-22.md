# 工位状态估计与活动计时实机审计

2026 年 11 月 22 日在 Jetson AGX Orin 上发布。更新的是 YOLO26m-Pose 关键点的解释、人体跟踪、Cosmos 复核、SQLite 计时及其读数。权重和用户配置沿用现场版本。

## 为什么同一张站姿照片看对，先坐后站却会多记坐姿

把已知坐姿和站姿照片依次送入真正的摄像头处理循环，每张保持 20 秒。第一轮中，模型和后处理最终能给出站姿，但刚切换后的 25 帧仍显示坐姿。SQLite 把站姿阶段的 5.01 秒记成了推测坐姿。单独测试第二张照片会漏掉这个问题。

旧的坐姿结论可以压过新帧里持续出现的肩、髋、膝变化。数据库还会等到下一次心跳才登记变化。新版要求局部关节方向至少持续 0.6 秒并有三帧支持，才能据此提前切换推测姿态。拍摄时间早于这次变化的复核结果随之失效。模型确认与推测分别记录。每次状态或推测来源类别改变，就按变化那一帧的采集时间写入。状态相同才按约一秒更新区间末端。

一次独立双阶段复测中，站姿阶段的前 4 帧保留了坐姿。从第 0.784 秒起持续显示站姿，此后 117 帧均为站姿。在这一段前面，SQLite 只多计了 0.64 秒推测坐姿。首次显示按发布时刻量，数据库按采集时刻分段，两者口径不同。

## 哪些证据会进入统计

| 场景 | 当前处理 |
|---|---|
| 人刚进入或只有偶发疑似人框 | 持续约 1.2 秒、至少三帧，并有重复且新近的人体证据，才开始计算在位。 |
| 单人站立、前倾、腿部不全 | 优先用可见肢段的相对几何与近期动作。落在图像填充或裁剪边界外的关节不参加估计。弱关节证据有独立的推测标记。 |
| 单人已确认在位，姿态线索不足 | 先参考近期或本次已确认的姿态。仅能确认有人时，按已有产品规则暂估坐姿。看板和问答注明推测部分。仅凭推测不会触发久坐提醒。 |
| 短暂遮挡、明确离开、多人或画面变化 | 单人短遮挡最多续计在位 15 秒。多人同框只计工位占用，个人姿态记未知。场景、追踪对象或观察连续性改变时清除相关旧证据。 |
| 没拍到人，椅背又可能挡住人 | 只有连续的明确空场复核才记离开。证据不足记未知。系统统计工位占用，没有身份辨认。 |
| 白天黑屏、暗场、缺帧和采集阻塞 | 黑屏立即关闭预览。北京时间 08:00–18:00 持续约 3 秒后开始记隐私。稳定变亮约 2 秒后恢复。发布的画面超过 3 秒仍未更新时，实时与校准接口拒绝旧图。已有心跳的采集循环连续 30 秒无发布，会请求受监督重启。 |

## 最终版本连续回放

在设备上比对部署文件与实验目录的哈希后，实际运行 96 秒。仅将摄像头输入换为依次重复的历史画面，保留实际采样时钟和推理耗时。为覆盖白天隐私策略，在实验进程中将昼夜选择固定为白天。每阶段中位帧率均为 6.2 FPS。

| 依次输入 | 最终版本的表现 |
|---|---|
| 已知坐姿，20 秒 | 入场后 1.40 秒持续显示坐姿，之后 113 帧均为坐。 |
| 已知站姿原帧，20 秒 | 前 4 帧仍坐，0.83 秒开始连续 118 帧显示站姿。数据库在该阶段计入 0.67 秒推测坐姿和 19.37 秒推测站姿。 |
| 白天黑屏，6 秒 | 38 帧均清除预览和骨骼，约 3.05 秒转为隐私保护。 |
| 用户指出的站姿截图，20 秒 | 从黑屏恢复算起 3.53 秒持续显示站姿，之后 104 帧均为站姿。这个延迟包含恢复亮度和重新确认入场。 |
| 真实空椅，30 秒 | 188 帧均为未知，在位与坐站累计均为零。该场景仍无法自动确认离开。 |

站姿截图与空椅素材的尺寸不同，会触发场景重置。这次切换用于检验空椅是否虚增坐站，不足以衡量同一机位的人从椅子旁走开后几秒确认离开。

## 计时和看板

- 在位、个人姿态、桌面状态在一个 SQLite 事务中登记。重复时间戳、时钟回拨、重启和长采样空洞均有回归用例。服务停机时没有观测的尾段不会凭空累加坐站。
- 日汇总、小时图和文字问答共用同一套区间裁剪、人工标注和短缺口补齐规则。跨午夜的缺口按实际秒数分到两天。人工标注也会避开隐私区间。
- 看板把连续坐姿从推测变为确认视为同一坐姿段，同时保留推测时长。小时图可查看没有任何记录的整点时段。站立目标达成以完整目标时长计算。看板的“今天”模式随北京时间跨日更新，连接中断会清除预览并标记上次数据。
- 统计问答支持今天、昨天、前天、明确单日和同问坐站。限定到某个上午或多个日期时会说明当前查询范围。查询未保存，数据留在 Orin。

## 实机验证与边界

- Orin 上 55 项自动化测试全部通过。额外用隔离 FastAPI 服务模拟白天黑屏、夜间暗场、拔摄像头、恢复及迟到的模型回复。
- 另一起独立进程在发送一张画面后模拟驱动阻塞。旧图被两个预览接口分别以 HTTP 423、503 拒绝。看门狗触发后该进程约 32.9 秒退出，现有每分钟守护任务已在生产机核对。
- 核对 14 天、8,680 条原始区间，未发现负时长或同轨重叠。每日坐、站、离开、隐私、未知之和逐项与 24 个小时柱相符，容差为每日取整的半秒。备份中的 27 条人工标注、1,492 条记录、2 项待办和两项设置都已核对保留。
- 实际浏览器从当天切到昨天，再回到今天，能显示最新汇总与小时提示，没有脚本错误。生产连读 30 次，帧号持续增加，帧率中位 6.2 FPS，最低一次 5.3 FPS。模型耗时中位约 124 毫秒。当天看板的在位、坐姿和站姿均为 0 秒，联合查询也返回坐、站各 0 秒。
- 7 张历史图中，3 张可见站姿和 1 张可见坐姿都判对。确认有人但被椅背遮住、确认是空椅的两张均判未知。另 1 张没有人工标签。照片反复播放能验证状态延续和记账，无法给出自然动作准确率或全天误差。原验收目标仍为切换延迟 P95 不超过 3 秒、坐时与站时误差各不超过 5%。

## 复现

在 Orin 上将此版本置于独立的源码目录，并把下列命令中的应用路径指向已有安装。生产服务可继续运行。隐私和看门狗测试各自绑定系统分配的回环端口。模型回放读取设备已有的照片、引擎和摄像头选区，使用临时数据库，与生产本机回环 Cosmos 服务通信。模型回放期间两份推理进程会共享 GPU。

```bash
app_dir="$HOME/Documents/orin-desk-agent"
export PYTHONPATH="$PWD"
export LD_LIBRARY_PATH="$app_dir/runtime/dla/usr/lib/aarch64-linux-gnu/nvidia:$app_dir/runtime/dla/usr/local/cuda-12.6/targets/aarch64-linux/lib:/usr/local/cuda/lib64"
"$app_dir/.venv/bin/python" -m unittest discover -s tests -v
"$app_dir/.venv/bin/python" experiments/privacy-camera-check/check.py
"$app_dir/.venv/bin/python" experiments/state-audit/check_watchdog.py
"$app_dir/.venv/bin/python" experiments/state-audit/check_snapshot.py "$app_dir/runtime/state-audit63/snapshot"
"$app_dir/.venv/bin/python" experiments/state-audit/replay.py --assets "$app_dir" --output /tmp/deskside-replay.json
```

在装有 Node.js 的 Mac 或开发机上，可以在源码目录执行 `node dashboard-smoke.js < dashboard.html`，验证跨日、断线恢复、估算分段、小时提示与目标进度。

本轮发布先比对旧版线上文件与 Git 基线，再备份代码和活动库，最后只重启 `orin-agent:vision`。Orin 的备份位于 `backups/state-audit-20261122-222615`。需要回退时，从该备份恢复本轮变更的 Python 文件和看板，在 `tmux` 中重启视觉应用。回退应用时继续沿用当前活动库即可。

Mac 项目证据目录为 `outputs/orin-desk-agent/evidence/63-state-audit/`，其中保留浏览器截图、运行日志、历史区间核对和回放汇总。Git 仓库只包含代码、测试与复现文档。
